# State-based death observer groups

After Pyroclasm or Infest, the engine selected creatures with lethal damage or zero toughness, then moved them sequentially. An observer removed first missed later deaths in the same state-based action group. Thirty regression cases reproduce twelve failures before this change, after correcting a test expectation to include Grim Haruspex's draw from a dying lord as well as a later Bear.

The private synchronous death-observer boundary introduced for destroy-all effects now also wraps each selected state-based graveyard group. Each group captures its observers, moves its selected objects, then queues notifications for actual creature deaths. The existing state-based loop runs again afterward. A creature made lethal by losing a continuous source belongs to that later group; an observer already gone cannot see its death. Empty groups do not allocate a snapshot. No persisted-state schema changes.

[StateBasedDeathObserverTest](../tests/Game/StateBasedDeathObserverTest.php) uses complete selected records from the pinned corpus: Zulaport Cutthroat (A25), Grim Haruspex (PLST), Pyroclasm (DSK) and Infest (CLU). Normalized-LF [fixture](../tests/Fixtures/state-based-deaths.json) SHA-256 is `a2b90b3b251a714c4b86c5f94c92e54ef497f01572ae951afe679d2e302879d3`; the test pins it, and the ledger pins that PHP source. Cases pay for the spell and cover both insertion orders, previous controller, self/other and token/nontoken restrictions, an opposing creature, and JSON replay before the spell and with death abilities on the stack.

Synthetic supporting cases distinguish successive groups after a lord dies, nonlethal damage, indestructible, regeneration and shield prevention. Zero toughness bypasses indestructible and regeneration. These cases are scoped regression evidence, not additional named corpus-card certificates.

This is a selected death-group notification boundary. It does not model every simultaneous state-based action atomically, snapshot all continuous characteristics, implement general replacement choices or APNAP player decisions, or fix simultaneous sacrifices. Selection still uses the existing prevention/replacement internals. General conditions and one-or-more-trigger event identity across different groups require separate review. The next measured family is simultaneous sacrifices with the same two pinned observers; heuristic sacrifice choices remain an explicit limit.

The ledger still contains five names with scoped evidence, three with explicit gaps and two in both dimensions. Recognition remains 11,282 of 28,729, with zero whole-card certificates. No environment contract changed, so `env.example` has no new entries. All checks are offline; no bot/Gaia startup, import, simulation, deployment or restart is part of this milestone.
