# Fixed-cost Ward execution contract

Comparison base: frozen draft #448, `e53f45cf44d6edab4e9fc2b471d19e38e43ca9b4`. This draft leaves #444–#448 unchanged and includes their explicit unmerged dependencies. Current exact-head checks and draft status must be read from GitHub. Draft publication does not enable the mode or establish readiness, merge or rollout; the older paid bare-target upgrade prerequisite remains.

## Rules boundary

Use the existing September 25, 2026 [Comprehensive Rules](https://media.wizards.com/2026/downloads/MagicCompRules%2020260925.pdf), 702.21a, 118.12a, 603.3a–d and 113.7a. True Ward fixes the event player's payer reference; Frost Titan's offending-controller wording remains separate. Each instance creates a non-targeting ability after successful targeting commitment. The original trigger survives source departure. Unless-payment remains optional even when the referenced entry is missing or uncounterable; only the exact referenced stack entry can be countered. Dynamic Ward costs and the second 603.3b phase for abilities triggered by another ability triggering are outside this fixed-cost slice.

## Implementation boundary

Execution is disabled by default and opt-in only at a quiescent engine boundary. It is persisted separately from ephemeral diagnostic observation. Empty older state migrates disabled. Fixed generic/colored/colorless mana and fixed life costs use validated WardInstance/Event snapshots. Unsupported discard, dynamic or legacy-equivalent clauses are refused before player action costs, or explicitly held when a queued automatic trigger cannot choose another target; no legacy fallback is silently certified. Genuine static targeting taxes remain casting costs.

Freeze the whole pending-trigger group at each priority checkpoint, with stable pending identities. Ask each controller to select that group's stack order in two-seat APNAP sequence, including their ordinary simultaneous triggers. Incremental next-on-stack choices use fresh choice IDs and paged panels; practice makes a documented deterministic selection through the same API. Triggers produced while placing a group wait for the next group; chosen ordering survives mode/target/payment pauses and JSON. No broad multiplayer/APNAP redesign is proposed.

Ward resolution offers a separately validated `ward_payment` choice whose payer can differ from the trigger controller. Accepted painful mana preserves one already-paid completion step through the existing damage continuation; replay never spends again. Decline uses the reviewed counter helper and source/copy identities. Missing and uncounterable entries make countering a no-op, rather than moving a source or a different entry. Source, instance, event, stack and choice identities remain distinct.

The earlier general pre-cost ordinary-target-trigger capture gap remains explicit; this work does not certify it. Retargeting and arbitrary replacement/continuous families, discard/dynamic Ward, legacy payer clauses, enabling cards, newest printings and whole-card certification remain outside. Tests use the existing cached Dog Walker record and clearly labelled enabling fixtures, without a corpus scan or live bot.

## Save compatibility and rollout prerequisite

Schema 20 persists the mode, event sequence and current whole-group ordering, including partial picks. Schema 17/18/19 saves migrate only to empty, disabled Ward state; they cannot inject active new state. This does not weaken schema 19's already-paid target refusal: schema 17/18 bare `o:id` pending targets cannot be safely assigned historical incarnations. Drain or finish affected pending actions under the old version before upgrade, or obtain an explicitly reviewed recovery policy if such records exist. No refund, cancellation, re-selection, replay, guessed incarnation or live-match inspection is part of this work.

Supported bounds: 128 distinct fixed Ward instances per targeting event; 256 target slots and pending-group entries; 256 remaining/followed resolution entries; 1 MiB Ward snapshot/payment choice, plus the existing damage continuation bounds. New event and pending-trigger sequences use bounded signed 32-bit positive identities; existing choice/stack identities retain their existing sequences and are checked against their saved next identity. Oversized or unsupported automatic groups/targets are held visibly, with no retry/refund control. Practice stops on a hold rather than looping or conceding.
