# Resumable creature-sacrifice choices

Barter in Blood previously chose each player's weakest creatures when more than two were eligible. Two paid-spell cases reproduced that behavior instead of requesting a decision. Each-player creature edicts without a greatest/least selector now use the existing pending-choice and resolution continuation mechanisms. This is a bounded choice family, not a general sacrifice engine.

The active player chooses first, followed by the other player. Players with no more than the required count need no input, but their creatures still wait for the other player's choice. Each decision has a monotonic identity, eligible object IDs and incarnations, and an exact count. No creature moves until all selections are complete. The engine validates the entire saved plan before accepting a new selection, so a changed previously selected object cannot cause a partial sacrifice. The existing death-observer batch handles the final group.

The practice bot makes its own conservative selection through the same engine API. Discord panels stage picks across 25-option pages, retain picks on other pages, support clearing, and enable confirmation only at the required count. The next chooser can see earlier public battlefield selections. Controls carry the current choice identity, so wrong-player, repeated, stale, off-page, duplicate and oversized selections fail without a persisted mutation. Staging uses temporary match storage in tests and does not advance the game. The existing generic interaction route forwards these controls; no new command registration is needed.

## Persistence

New saves use `schemaVersion: 5`. Version-4 and earlier supported records retain their existing migration paths; delayed-draw state remains mandatory from version 3 onward. A pending sacrifice decision requires version 5, complete groups and a valid resolution continuation. Malformed identities, inconsistent seats/counts, invalid selections, skipped players, changed incarnations and missing continuation state are rejected. Older version-4 builds reject version 5 before hydrating game data. Do not manually downgrade the schema label or resume a version-5 match on an older build.
