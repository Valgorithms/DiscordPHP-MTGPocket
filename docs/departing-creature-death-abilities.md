# Departing creature death abilities

`moveTo()` clears transformation and face-down state before queuing a creature's own death ability. Reading its new graveyard definition then selected the front face's ability, even if it had a different back-face ability or had no abilities while face down.

Reuse the immutable battlefield definition captured for death subtype observers when selecting the source's own `dies` abilities. Labels and CARDNAME substitution use that definition's name. The actual graveyard object, its new incarnation and the existing `graveyardSelf` handling remain available to effects that return it. The pre-move controller still controls the trigger. This implements the bounded static-face look-back required by rules 603.10/603.10a of the [official Comprehensive Rules](https://media.wizards.com/2026/downloads/MagicCompRules%2020260619.pdf).

`DepartingCreatureAbilityTest` uses synthetic faces with different death effects, activated transformation, paid face-down casting and paid removal. The ordinary front face is a positive control. The transformed, face-down, back-face self-return and stolen-back-face cases all fail before the fix (5 tests / 40 assertions / four failures). With the fix, the combined departing-ability, subtype and animated-death tests pass: 20 tests / 284 assertions. Actual JSON records resume both pending removal and already-stacked death triggers; replay is deterministic. The back-face self-return case verifies that the new graveyard incarnation is returned correctly rather than confusing it with the departed battlefield object. Pint passes both changed PHP files under the 30-second cap.

No parser recognition increase or whole-card functional percentage is claimed. General simultaneous departing observers, continuous/gained/lost abilities, full last-known information, source-dependent conditions and the separate `leaves`/`to_graveyard` event families still require their own work. Parser and saved-state shape are unchanged; `env.example` needs no new variables. No import, live bot, build, restart or deployment is included.
